# Open Source Growth Plan

This plan turns the repository review into a practical backlog for Hackerrank Problems.

## Quick wins

- Add a progress table by domain, language, and difficulty.
- Add links from each solution to the related HackerRank challenge.
- Add automated compile/test checks for C++ and Java solutions.
- Add a consistent naming convention for problem folders and files.
- Add contribution guidance for adding new solutions and explanations.
- Add `good first issue` tasks for missing explanations, tests, and Python solutions.

## Bugs and bad practices to watch

- Hard-coded sample input that prevents reusable tests.
- Missing complexity notes for algorithms.
- Inconsistent formatting across languages.
- Solutions that pass examples but fail edge cases.
- Duplicate implementations without explanation.

## Star growth strategy

1. Add a clear progress dashboard in the README.
2. Add explanations for each solution, not only code.
3. Add GitHub topics such as `hackerrank`, `algorithms`, `data-structures`, `cpp`, and `java`.
4. Add beginner-friendly issues for porting solutions to Python.
5. Share the repo as a structured interview-practice resource.

## Trending-library opportunities

- Use Pyrefly-style static checks when Python solutions are added.
- Use LangExtract-style scripts to extract problem metadata into a progress table.
- Use MarkItDown-style generation for solution notes and README summaries.

## Suggested next PRs

- Add CI compilation for C++ and Java.
- Add a generated problem index.
- Add templates for solution explanations.
